# 現場の困りごとを、Claude Codeと動く道具にする

養鶏場の仕事を続けながら、使う場面を言葉にし、Claude Codeと設計・実装・テスト・修正を進めてきました。
何を作るか、どこまで公開するか、業務上の判断をどう扱うかは作者が決めます。

## 一つの変更を進める流れ

1. **使う場面を説明する** — 何を記録し、誰が確認し、間違うと何に困るかを言葉にします。
2. **条件を確かめる** — 接続や実機での挙動など、設計の前提を確認します。
3. **処理とテストを作る** — 日付・金額・権限・再送といった境界の条件を含めます。
4. **別の視点で確認する** — 実装した内容をレビューし、実行結果を確かめます。
5. **自分で使って戻す** — 実機や日常の利用で出た問題を、次の要件と検証へ戻します。

開発の中心はClaude Codeです。2026年10月からはCodexにも実装・調査・レビューの一部を任せています。
設計書、確認した事実、事故の原因と再発防止を記録し、作業を引き継げるようにしています。

## 具体例へたどる

| 作者が言葉にする条件 | 実装・テストとして読む事例 |
|---|---|
| 在庫を途中から計算しても答えが変わらないこと | [全期間の再計算との一致](../case-studies/shipment-inventory.md) |
| 入金の許容差と、締めを確定できる人が明確なこと | [境界と権限の判定](../case-studies/month-end-review.md) |
| 記録の訂正を人が確認し、元の版を残せること | [下書き・確認・適用と版管理](../case-studies/receipt-corrections.md) |

これらは、利用時に守りたい条件を、処理とテストへ落とし込んだ例です。
作業時間の削減率や誤りの減少率は測定していないため、効果の数値としては掲載していません。
