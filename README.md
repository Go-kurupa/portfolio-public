# 養鶏場の現場から、Claude Codeとつくる業務アプリ

**卵の数を記録する。餌の量や配送先、人の予定を確認する。卵を届け、残った在庫と売上を確かめる。養鶏場で日々使うアプリを、経営する本人が作っています。**

養鶏場経営に参画しながら、独学でアプリを作っています。2026年2月からClaude Codeと開発を続け、現在は7つの業務アプリを日々の仕事で使っています。
このリポジトリは、Built with Claude Japan 2026への応募に向けてまとめた、大会前からの開発実績です。大会中に作る新しい企画は別途決定します。

## 現場の課題

養鶏場の仕事には、卵の数や死亡羽数を記録する作業、餌の量を計算する作業、人と仕事の予定を組む作業があります。
さらに、注文ごとの出荷、委託先の在庫、売上と入金、月次の締めまで確認が続きます。

アプリを作る際には、期限切れの在庫をどう扱うか、訂正前の記録をどう残すか、誰が月の記録を確定できるかといった条件も決める必要がありました。
私は業務を使う立場からその条件を言葉にし、処理とテストで確かめられる形へ落とし込んできました。

## アプリで何をするか

| 仕事で確認したいこと | 使うアプリ | 扱う情報・できること |
|---|---|---|
| 卵がいくつ取れたか | 集卵数カウント | 日付・鶏舎・サイズ別に卵の数を記録する |
| 飼育中の鶏の変化を残したい | 死亡羽数管理 | 部屋ごとに雄・雌別の死亡数とメモを残す |
| 今日与える餌の量を決めたい | 餌量計算 | 残餌や持越量を踏まえて給餌量を計算・記録する |
| 誰がいつ働く予定か | シフト管理 | 勤務希望を集め、管理者が予定を調整・公開する |
| 日々の仕事を一覧で見たい | 業務リスト | 作業ごとの担当者・チェックリスト・完了記録を管理する |
| 何を出荷し、在庫がどれだけ残るか | 出荷管理 | 販路別の出荷予定・記録と、委託先の在庫を扱う |
| 現場と会計の数字を確かめたい | 経営ダッシュボード | 売上と入金を照合し、月の記録を確定する判断につなげる |

作者本人が、記録・計算・予定・出荷・経営の確認に使っています。各アプリの用途と、この資料に掲載している説明・コードの範囲は[アプリ一覧](./docs/app-catalog.md)にまとめています。
表は人が行う仕事の役割を示しています。アプリ間の自動連携の構成図ではありません。

周辺では、スマートフォンで保管した領収書を会話から検索・整理する[領収書保管](./case-studies/receipt-corrections.md)と、用途別の対話窓口となるDiscordボット群も作っています。
スナップOCRも個人用に試作していますが、ソースと実装の詳細は非公開で、今回のソース提出対象には含めていません。

## 使う流れから分かる3つの事例

| 事例 | 仕事の中で行うこと | そのために確かめる条件 |
|---|---|---|
| [委託先に残る在庫を計算する](./case-studies/shipment-inventory.md) | 納品した数から、売れた分と期限切れを差し引く | 途中から計算し直しても、最初からの計算と同じ結果になる |
| [売上と入金を照合する](./case-studies/month-end-review.md) | 売上を入金へ対応付け、月の記録を確定する | 差額・日付・操作できる人の条件が守られる |
| [会話から領収書を訂正する](./case-studies/receipt-corrections.md) | 候補を探し、変更案を人が確認して反映する | 訂正前の記録を残し、同じ要求の二重反映を防ぐ |

各事例は「課題 → 作者が決めた条件 → 実装 → 確認できる証拠」の順で読めます。

各アプリの概要：[シフト管理アプリ](./apps/shift-management/README.md) ／ [出荷管理](./apps/shipment-management/README.md) ／ [業務リストアプリ](./apps/task-management/README.md) ／ [経営ダッシュボード](./apps/management-dashboard/README.md) ／ [集卵数カウントアプリ](./apps/egg-count/README.md) ／ [餌量計算アプリ](./apps/feed-calculator/README.md) ／ [鶏死亡羽数管理アプリ](./apps/flock-mortality/README.md)

## Claude Codeと作者の分担

| 作者が担うこと | Claude Codeが支援すること |
|---|---|
| 使う場面、業務の判断、守る条件、掲載範囲を決める | 設計案、コード、テスト、原因調査、修正を作る |
| 実機と日常業務で確認し、次の課題を伝える | 確認結果を受け、処理とテストを更新する |

2026年10月からはCodexにも実装・調査・レビューの一部を任せています。
開発を支援するAIの役割と、作者が判断する業務の条件を[開発過程](./docs/development-process.md)にまとめています。

## 検証の範囲

在庫の計算経路、金額・日付の変わり目、権限、訂正の履歴など、仕事で間違えると困る条件をテストで確かめています。
元アプリの2026-10-14時点の通過件数は[検証記録](./docs/verification.md)にまとめています。これは過去の非公開の検証記録をもとにした説明で、掲載した抜粋だけから全件を再現できるものではありません。

コード抜粋は依存する型定義や業務システムを省いているため、このリポジトリ単体では実行できません。
削減時間・売上増・ミス削減率について、比較測定していない数値は掲載していません。
